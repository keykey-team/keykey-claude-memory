## 🆕 Стратегія уточнена — «3 кити» (страт-планерка 16.06 [транскрипт 381be…d041a])
- **Продуктова екосистема = 3 кити:** сайт + AI-агент + CRM (KEY SPACE) — різні, але працюють у одній зв'язці, усі навколо **ПРОДАЖІВ**.
- **AI-агент = інструмент продавця, НЕ повноцінний продавець:** працює 24/7, будь-якою мовою, не губить ліди, піднімає конверсію. Цінність прямо прив'язана до грошей клієнта (ріст конверсії → ріст виручки видно одразу).
- **Сегментація — у бік процесу продажів, а не вузьких ніш.** При малій кількості замовлень не відмовлятися від великих чеків з будь-яких сфер. Експертизу качають у HoReCa/нерухомості (як RGB), але беруть і інших.
- **Свідомі межі:** НЕ лізти у фінанси/ERP та маркетингову стратегію клієнта — слабка експертиза («у фінансах ми лохи»). Максимум — IT-тех-партнер.
- **Монетизація-ідеї:** (1) відсоток від росту продажів клієнта — визнано складним у реалізації; (2) продавати не лише реалізацію, а й **експертну обробку скриптів** продажів клієнта (структурування, відсів неефективних).
- **Claude як тимчасове ядро:** поки власне AI-ядро ONEQ зробити не можуть — Claude закриває цю роль; згодом докрутять до власного продукту. 🟢 ~15.06 отримано **першу оплату за AI-продукт** (деталі → log/decisions.md 17.06).

- **AI бюджет:** ≤5% від вартості проєкту ($50-100 для $1,000-2,000 проєктів)
- **Правило архітектури:** ніколи фронт → БД напряму. Завжди: Frontend → Backend → Database
- **ТЗ для AI:** завжди включати безпеку + архітектуру + масштабованість + підтримку
- **Льова (дизайнер):** AI скоротив роботу з 8-9 год → 2-3 год (AI насмотренность → 30-50 посилань)
- **Цільовий процес (June 5):** клієнт → sales збирає контекст → PM/AI уточнює → AI оформляє проєктну документацію → автостворення задач
